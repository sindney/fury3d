## Why

The editor viewport has three structural pain points that this change resolves together. First, there is no dockable "Viewport" window — the 3D scene renders straight to the SFML back buffer and shows through the dockspace's `PassthruCentralNode`, so it cannot be docked, tabbed, or resized independently like every other editor panel. Second, picking and camera-drag both fire on plain left-mouse-down over the central region, so any click-look also selects (or deselects) whatever node happens to be under the cursor; the two operations are conceptually distinct but structurally coupled. Third, selecting a node gives no visual feedback — there is no outline, no bounding box, no light-volume gizmo — even though the engine already has the wireframe sphere/cone/AABB drawing code (used by the Profiler's debug overlays) that could be reused. The archived `2026-06-26-add-3d-picking-and-gizmo` design explicitly calls out that gizmo + picking would need to switch from full-window space to viewport-window space once a docked viewport is introduced — this is that change.

## What Changes

- Add a dockable **"Viewport"** ImGui window that displays the 3D scene rendered to an offscreen color+depth render target, `ImGui::Image`-d into the window's content rect. The camera projection's aspect is re-derived from the content rect each frame.
- Drop `ImGuiDockNodeFlags_PassthruCentralNode` from the dockspace and add the Viewport window to the default layout as the center-docked tab.
- Switch `ImGuizmo::SetRect` from the full SFML window's pos/size to the Viewport window's content rect, so the TRS gizmo lands on the selected node inside the docked viewport. **BREAKING** (at the spec level) for `editor-shell`'s gizmo requirement, which currently mandates full-window space.
- Switch `Picking::RequestPickAt` from full-SFML-window pixel coordinates to Viewport-window-content-rect-relative pixels, and size the picking FBO to the viewport's actual size instead of the whole SFML window. **BREAKING** (at the spec level) for `viewport-picking`, which currently mandates full-window coordinates.
- Decouple picking from camera-drag: a pick is scheduled only on a true click — left button press and release at (approximately) the same screen position, with no drag in between. A press that moves (a camera-drag) does NOT schedule a pick. Picking nothing on a true click deselects the current selection.
- Add editor-only **selection visualization**: when a `SceneNode` is selected, draw a wireframe outline — the node's world AABB for mesh nodes, the point-light sphere (scaled by `Light::GetRadius()`) for `LightType::POINT`, and the spot-light cone (already pre-shaped by radius/outer angle in `Light::EvaluateVolume`) for `LightType::SPOT`. Reuses the existing `RenderUtil::DrawBoxBounds` / `RenderUtil::DrawMesh` wireframe API that the Profiler's debug overlays already use.
- Wire a `Signal<SceneNode*>` selection-changed event so the selection-visualization (and other future consumers) react to selection changes rather than polling `g_SelectedSceneNode` every frame. Add a public Lua accessor for `Picking::IsPickInFlight()` so the `Editor.lua` camera-drag can short-circuit while a pick is resolving (defense in depth alongside the click-vs-drag gate).

## Capabilities

### New Capabilities
- `editor-viewport-window`: A dockable ImGui "Viewport" window that presents the 3D scene rendered to an offscreen render target. Covers the render-target lifecycle, the `ImGui::Image` blit, aspect-ratio derivation from the window's content rect, and the window's input-routing contract (hover/focus gating for clicks inside the viewport).
- `selection-visualization`: Editor-only wireframe overlay drawn for the currently selected `SceneNode` — world AABB for mesh nodes, sphere for point lights, cone for spot lights — reusing the existing `RenderUtil` debug-draw primitives.

### Modified Capabilities
- `viewport-picking`: Pick coordinates switch from full-SFML-window space to Viewport-window content-rect space; the pick is scheduled on a true click (press + release at the same spot, no intervening drag) rather than on the mouse-down edge; picking nothing on a true click deselects. The picking FBO is sized to the viewport, not the SFML window.
- `editor-shell`: The TRS gizmo's `ImGuizmo::SetRect` switches from the full SFML window's pos/size to the Viewport window's content rect; the default dock layout gains a center-docked Viewport window and drops `ImGuiDockNodeFlags_PassthruCentralNode`; a `Viewport` toggle is added to the `Window` menu and to `Editor::SetWindowVisible` / `GetWindowVisible`.

## Impact

- **Code**: `engine/Fury/Editor/Editor.cpp` (Tick orchestration, dockspace flags, default layout, window-menu, click-capture), `engine/Fury/Editor/EditorGizmo.cpp` (rect source), `engine/Fury/Editor/EditorPicking.{hpp,cpp}` (coordinate space, click-vs-drag state machine, FBO sizing), `engine/Fury/Editor/EditorWindows.cpp` (new `RenderViewportWindow`, selection-viz draw call site), `engine/Fury/Editor/Editor.h` (new `Viewport` window name in the visibility switch, selection-changed signal accessor), `engine/Fury/PrelightPipeline.{hpp,cpp}` (optionally render to a provided offscreen RT instead of the default framebuffer), `engine/Fury/RenderUtil.{hpp,cpp}` (no new API needed — reuse existing), `examples/Editor.lua` (camera-drag uses `Picking::IsPickInFlight()` gate; camera aspect re-derived from viewport rect).
- **Specs**: Amends `editor-shell/spec.md` (gizmo rect requirement, default layout requirement, dockspace flags) and `viewport-picking/spec.md` (coordinate-space requirement, trigger requirement, deselect requirement). Adds `editor-viewport-window/spec.md` and `selection-visualization/spec.md`.
- **APIs**: New `Editor::OnSelectionChanged` signal accessor; new Lua-exposed `Picking::IsPickInFlight()`; pipeline `Execute` gains an optional render-target argument (default keeps current back-buffer behavior for non-editor builds).
- **Dependencies**: No new third-party dependencies. Reuses ImGui docking (already enabled), ImGuizmo (already integrated), and the engine's existing `Texture` / FBO infrastructure.
- **Non-editor builds**: `WITH_EDITOR` off is unaffected — the render-to-back-buffer path remains the default when no editor viewport RT is supplied.
- **Migration**: Users with a saved `imgui.ini` will have the new Viewport window spawn as a floating tab on first launch until they re-dock it; the `Window → Reset Layout` action places it in the center as intended. No serialized scene format changes.
