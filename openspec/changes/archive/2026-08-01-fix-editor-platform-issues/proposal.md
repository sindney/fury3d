## Why

The furye editor has three Windows-first (and one macOS-adjacent) regressions that all show up at the platform boundary — input, focus, and DPI:

1. **IME overflow crash.** When the Windows IME is set to Chinese, pressing WASD crashes the editor. Root cause: `Engine::HandleEvent` at `engine/Fury/Engine.cpp:159` writes `m_KeyDown[static_cast<unsigned int>(key->code)] = true` with no bounds check. `sf::Keyboard::Key::Unknown` is `-1` (cast to `0xFFFFFFFF`). The SFML Win32 backend's `virtualKeyCodeToSF()` returns `Key::Unknown` for any `wParam` it does not recognize, including `VK_PROCESSKEY` and IME composition virtual keys — and SFML still pushes those `KeyPressed` events into the queue. With the IME active, the engine writes ~4.3 billion entries past the end of `m_KeyDown[]`, corrupting adjacent memory and crashing.
2. **Mouse drag dead on first launch.** Left-mouse drag does not start a viewport drag (no pick, no gizmo drag, no camera orbit) on the very first interaction. Toggling the window to the background and back once restores drag, and on macOS the same symptom appears after the native open-file dialog returns. Root cause: `InputUtil::m_WindowFocused` defaults to `false` (`engine/Fury/InputUtil.h:27`), and Windows does NOT auto-fire `WM_SETFOCUS` for a window shown via `CreateWindowW(... WS_VISIBLE ...)` (which SFML uses at `engine/ThirdParty/SFML/src/SFML/Window/Win32/WindowImplWin32.cpp:190`). SFML's Win32 backend only maps `WM_SETFOCUS`/`WM_KILLFOCUS` to `Event::FocusGained`/`FocusLost` — it does NOT handle `WM_ACTIVATE`. So the `m_WindowFocused` flag stays at its `false` initial value until the user manually triggers a focus transition (alt-tab, title-bar click). The Lua drag gate at `examples/Editor.lua:705` reads `lmb_down = focused and has_mo and input:GetMouseDown(MouseButton.Left) ...`, so drag is dead. On macOS, NFD's `IFileOpenDialog::Show` is modal and Windows-shell-managed; the parent HWND never receives `WM_SETFOCUS` after the dialog closes, so the same flag stays `false` permanently until a manual focus event.
3. **GUI too small on Windows HiDPI.** At 200% system display scale the editor window renders at native pixel size with no DPI awareness — the ImGui style is still scaled at `1.0` (set as the default in the `fix-demo-fps-profiler-retina` change), so every dock, button, and label is half the expected size. The fix that bumped the default from `2.0` → `1.0` solved macOS Retina double-scaling but left Windows HiDPI uncovered: the engine never declares DPI awareness and never reads the system DPI to seed `EngineOptions::gui_scale`.

We fix all three together because they share the same touch points (`Engine::Initialize`, `Engine::HandleEvent`, `Gui::Initialize`, `EngineOptions`) and the user has confirmed they are all blocking the Windows build. Each fix is small and isolated; bundling them is a documentation/effort win, not a coupled design.

## What Changes

- **IME safety in `Engine::HandleEvent`** (Windows-specific, guarded with `PLATFORM_WINDOWS`): bounds-check `sf::Event::KeyPressed` and `KeyReleased` codes against `[0, sf::Keyboard::KeyCount)`, dropping events whose `code == sf::Keyboard::Key::Unknown` (or otherwise out of range). This is the actual fix for the Chinese-IME crash — SFML's Win32 backend pushes `Key::Unknown` events for `VK_PROCESSKEY` and IME composition virtual keys, and the previous code wrote past the end of `m_KeyDown[]`. The bounds-check is wrapped in `#if PLATFORM_WINDOWS` from the new `PLATFORM_WINDOWS` macro in `engine/Fury/Macros.h` (introduced by this change alongside `PLATFORM_MACOS`, `PLATFORM_LINUX`, etc.). Also rate-limit `TextEntered` per frame to defend against IME composition text floods, and track IME composition state on `InputUtil` so the editor's shortcut routing can skip while composing.
- **Focus-driven mouse seeding**: on `FocusGained`, poll the current cursor position via `sf::Mouse::getPosition(window)` and seed `m_MousePosition` + emit one `OnMouseMove` before the user can click. Reset any "stuck" key/button state on `FocusGained` as defense-in-depth (the `FocusLost` branch already drops held keys; make the symmetry explicit). On macOS, do the same seed on `sf::Event::MouseEntered` returning `true` after the native open dialog dismisses.
- **Initial focus state fix**: in `Engine::Initialize`, after creating the window, call `window.hasFocus()`. If it returns `true` (the typical case when the launching shell is not in the foreground), set `InputUtil::m_WindowFocused = true` and emit `OnWindowFocus(true)` BEFORE `Engine::Run` starts polling events. This corrects the `m_WindowFocused = false` default in `InputUtil.h:27` for the common case where Windows gives focus to the new window at creation time but does not fire a `WM_SETFOCUS` message that SFML would translate. The existing `FocusLost`/`FocusGained` event handlers still own the rest of the focus state machine; this is a one-shot bootstrap.
- **DPI awareness on Windows** (Windows-specific, guarded with `PLATFORM_WINDOWS`):
  - Ship `engine/Resources/fury.exe.manifest` declaring `<dpiAwareness>PerMonitorV2</dpiAwareness>`. The existing engine build (`engine/CMakeLists.txt`) does NOT set any application manifest today — `<GenerateManifest>true</GenerateManifest>` is the MSVC default which produces a stock manifest with no `<dpiAwareness>` element. SFML's Win32 backend only calls `SetProcessDpiAwareness(ProcessPerMonitorDpiAware)` (not V2, not `SetProcessDpiAwarenessContext`) at `engine/ThirdParty/SFML/src/SFML/Window/Win32/WindowImplWin32.cpp:70-125`, so the editor process is "Per Monitor DPI Aware" (v1) at best. Per-monitor V2 is the right choice for the editor because it (a) re-issues `WM_DPICHANGED` when the user drags the window between monitors, and (b) gives the OS enough information to apply automatic non-client-area scaling. The manifest is linked via `set_target_properties(fury furye PROPERTIES LINK_FLAGS "/MANIFESTINPUT:${PROJECT_SOURCE_DIR}/Resources/fury.exe.manifest")` gated by `if(PLATFORM_WINDOWS)` (which currently resolves to `if(WIN32)`).
  - At `Engine::Initialize` time, read the system DPI via `GetSystemDPI()` whose three implementations are guarded with `#if PLATFORM_WINDOWS` (Win32 `GetDpiForSystem`), `#if PLATFORM_MACOS` (`[NSScreen mainScreen].backingScaleFactor` via the new `Engine_dpi_mac.mm` shim — currently returns 1.0 because SFML 3 macOS forces `highDpi=NO`, but the call is in place for the future Retina-rendering path), and `#if PLATFORM_LINUX` (hard-coded 1.0). Map DPI to `EngineOptions::gui_scale` if the caller did not pass one explicitly.
  - Also fix the deprecated `io.FontGlobalScale = fontScale` write in `engine/Fury/Gui.cpp:48` to use `style.FontScaleMain = fontScale` (the ImGui 1.92 replacement, see `engine/ThirdParty/ImGui/imgui.cpp:543` deprecation comment). The legacy field still works, but `FontScaleMain` is the supported path. `m_GlobalScale` in `Gui.cpp:22` is dead state — leave it; not in scope. This change is cross-platform (no `PLATFORM_*` guard) — ImGui's API is the same on every platform.
  - Add a new `EngineOptions::dpi_aware_override` (default `false`) that, when `true`, forces the computed DPI to apply on top of any explicit `gui_scale` (so a user passing `gui_scale = 1.0` still gets system-DPI scaling unless they also pass `dpi_aware_override = true`). Documented opt-in for scripts that want pixel-perfect UI.
- **EngineOptions extension**: add `text_event_max_per_frame` (default `64`) and `dpi_aware_override` (default `false`). Existing callers without these fields see no behavior change.
- **Editor adjustment**: the editor's menu/window rendering MUST tolerate the new IME composition state by suppressing shortcuts that would otherwise fire while an IME is composing (e.g. `Ctrl+S` is currently always routed; it should not fire if `OnIMEStateChanged(true)` is the latest state and the cursor is in a text input).
- **Documentation**: a short note in `docs/ARCHITECTURE.md` covering Windows DPI awareness, the IME composition contract, and the focus-mouse seed behavior, mirroring the SFML-3-HiDPI note already present.

## Capabilities

### New Capabilities

- `platform-input`: the engine's input-layer contract for cross-platform correctness — IME composition state, `TextEntered` flood protection, focus-aware mouse seeding, and a stable cursor position for the first frame after focus. Reusable by any future platform (Linux, Web).
- `platform-window-dpi`: the engine's per-platform DPI awareness declaration, system-DPI read at init, and the `EngineOptions` knobs that let scripts control or override the resulting `gui_scale` / `gui_font_scale`. Reusable for true Retina on macOS in a later change.

### Modified Capabilities

- `lua-input`: extend the `Engine.run` options table to accept `dpi_aware_override`. No new C++ / Lua surface beyond the existing input accessors.

## Impact

- **Code**:
  - `engine/Fury/Macros.h` — add the `PLATFORM_WINDOWS` / `PLATFORM_MACOS` / `PLATFORM_LINUX` / `PLATFORM_IOS` / `PLATFORM_ANDROID` / `PLATFORM_DESKTOP` / `PLATFORM_MOBILE` macros at the top of the file. Each macro resolves to `1` on its target and `0` elsewhere; the aggregates are `OR`d combinations of the per-platform macros. Existing code in the engine that uses `defined(_WIN32)` / `__APPLE__` / `__linux__` is unchanged in this commit; only the new macros are added.
  - `engine/Fury/Engine.{h,cpp}` — bounds-check `KeyPressed`/`KeyReleased` codes against `[0, sf::Keyboard::KeyCount)` (guarded with `#if PLATFORM_WINDOWS`) to fix the IME crash; add `EngineOptions::text_event_max_per_frame` + `dpi_aware_override`; add IME composition tracking to `HandleEvent` (Windows-specific code path guarded with `#if PLATFORM_WINDOWS`); add focus-driven mouse seeding on `FocusGained` (cross-platform); bootstrap `m_WindowFocused` from `window.hasFocus()` in `Engine::Initialize` to fix the first-launch drag bug (cross-platform); read `GetDpiForSystem` (Windows, `#if PLATFORM_WINDOWS`) / `[NSScreen mainScreen].backingScaleFactor` (macOS, `#if PLATFORM_MACOS`) / 1.0 (Linux, `#if PLATFORM_LINUX`) as `Engine::GetSystemDPI()`; apply DPI to `gui_scale` when the caller passed `gui_scale == 0` (new sentinel for "use system DPI") or `dpi_aware_override == true`.
  - `engine/Fury/InputUtil.{h,cpp}` — new `OnIMEStateChanged(bool)` signal, `IsIMEComposing()` accessor, `ResetTransientInputState()` helper that zeros held keys/buttons/position on demand. Cross-platform; the composition-state field is set by the Windows-specific path in `Engine.cpp` and remains `false` on other platforms.
  - `engine/Fury/Gui.cpp` — replace the deprecated `io.FontGlobalScale = fontScale` write at line 48 with `style.FontScaleMain = fontScale` (ImGui 1.92 rename). Keep `style.ScaleAllSizes(scale)` as-is. Cross-platform.
  - `engine/Fury/Gui.cpp` — `Gui::Initialize` already accepts `gui_scale` and `gui_font_scale`; no new code, but the call site changes to pass the DPI-derived default when the user opts in.
  - `engine/CMakeLists.txt` — Windows-only target link of `engine/Resources/fury.exe.manifest` via `set_target_properties(fury furye PROPERTIES LINK_FLAGS "/MANIFESTINPUT:...")` gated by `if(PLATFORM_WINDOWS)`. macOS / Linux untouched. Also for the macOS DPI read, add a tiny `engine/Fury/Engine_dpi_mac.mm` (Objective-C++) that returns `[NSScreen mainScreen].backingScaleFactor`; the file is appended to `FURY_COMMON_SRC` only when `PLATFORM_MACOS` is true.
  - `engine/Resources/fury.exe.manifest` (new) — single-file XML with `<dpiAwareness>PerMonitorV2</dpiAwareness>` and `<dpiAware>true</dpiAware>` fallback.
  - `engine/Fury/Editor/Editor.cpp` — guard shortcut routing in `Editor::Tick` behind `Editor::IsIMEComposing() == false`.
  - `engine/Fury/LuaBindings.cpp` — expose `InputUtil.IsIMEComposing()`; document the two new `Engine.run` keys.
- **Public API**:
  - C++: `InputUtil::OnIMEStateChanged` signal, `InputUtil::IsIMEComposing()`, `InputUtil::ResetTransientInputState()`. `EngineOptions` gains two fields (defaults preserve behavior).
  - Lua: `InputUtil.Instance():IsIMEComposing() -> bool`, `Engine.run(callbacks, options)` options table gains `text_event_max_per_frame` and `dpi_aware_override`.
- **Behavior**:
  - Windows at 200% scale: editor GUI is sized ~2× (proportional to DPI); mouse drag works on first launch; Chinese IME no longer crashes on WASD.
  - macOS unchanged for the IME crash (the path doesn't fire) and mouse-drag (the existing `FocusLost`/`FocusGained` cleanup at `Engine.cpp:130-150` already covers most cases — the new seed-on-focus just makes the first interaction reliable too).
  - Linux unchanged; the new code paths no-op when no IME is active and the OS reports DPI = 96.
- **No new submodules, no dependency bumps, no asset-format changes.**
- **Out of scope**:
  - True Retina rendering on macOS (would require an SFML patch; documented as future work in `docs/ARCHITECTURE.md` §16).
  - Per-window-resize DPI change (Windows can change DPI when a window is dragged between monitors; we read DPI once at init, matching the existing once-at-initialize GUI scale contract).
  - IME support in the editor's text inputs beyond composition detection (the existing `InputText` widgets already handle unicode codepoints via `OnTextEntered`).
