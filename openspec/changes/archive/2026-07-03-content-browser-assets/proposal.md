## Why

Today the Content Browser is a cosmetic, read-only flat file list (`[J] foo.json`, `[B] foo.bin`, …) that does nothing on click and has no thumbnails, no context menu, no double-click, and no relationship to the assets actually living in the active scene. Meanwhile `Mesh` and `Material` are first-class shared assets stored in the scene's `EntityManager` and referenced by name from many `MeshRender` components, but the editor has no way to *see*, *rename*, *duplicate*, *delete*, or *edit* those assets directly — and the `MeshRender` inspector block is read-only, so rebinding a mesh or material to a node is impossible without editing JSON by hand. This change turns the Content Browser into a real asset browser (Unity/UE-style icon grid) and makes the inspector an actual two-way binding surface with the assets it references.

## What Changes

- **Content Browser becomes an asset grid, not a file list.** The window renders in-scene assets (every `Mesh` and `Material` registered in the active `Scene`'s `EntityManager`) as icon tiles in a wrapping grid (Unity/UE4 style), not a single-column `Selectable` list. Each tile shows a thumbnail (texture for materials/textures, mini-3D render for meshes) and the asset's unique name. The directory file list is removed from this window (file open/import/save stay in the File menu and modals).
- **Asset unique-name enforcement, shared with nodes.** A single engine-level unique-name helper (`UniqueName(base, existsPredicate)`) replaces the editor-only `UniqueChildName` static in `EditorWindows.cpp`. Both asset rename and node rename route through it. `EntityManager::Add` already silently drops duplicates today; the editor now surfaces collisions before they happen and proposes a `Name`, `Name (1)`, `Name (2)` suffix on rename/duplicate.
- **Context menu on assets: Duplicate / Rename / Delete.** Right-click on an asset tile opens a context menu. Duplicate clones the asset (deep copy of Mesh / Material data) and registers it under a unique name. Rename enters inline edit (Enter commits, Esc cancels, empty/colliding names fall back to a unique variant). Delete removes the asset from the `EntityManager`.
  - **Delete-in-use guard:** Before deleting, the editor counts how many `MeshRender` components across the scene reference the asset. If the count is non-zero, a confirm dialog pops up warning "Asset is in use by N MeshRender(s). Delete anyway?" with Yes/No. Confirmed deletes proceed and leave dangling weak_ptrs (existing `GetRenderable()` already handles expired weak_ptrs).
- **Generalized Yes/No confirm dialog.** A small reusable `Editor::ConfirmDialog` modal (flag-then-`OpenPopup` pattern mirroring `g_SaveAsModalOpen`) with a title, message, and Yes/No callback. Used by the delete-in-use guard and available for future confirm flows (discard unsaved changes, etc.). Not used for trivial 2-3 line confirms.
- **Double-click asset → asset editor window.** Double-clicking a Mesh or Material tile opens a modal editor window for that single asset. The window walks the asset's serializable properties and renders editable widgets for each: textures get a thumbnail + path + srgb/filter/wrap controls (reusing the material texture row pattern), uniforms get typed editors (ColorEdit4 / DragFloat / etc. by runtime uniform type), mesh metadata shows vert/index/tri counts, AABB, submeshes, joints. Meshes additionally render a small 3D preview pane with the mesh centered in view, camera framed by the mesh's AABB, with **rotate (drag) + zoom (wheel)** only — no pan. `ImGuizmo::ViewManipulate` (the upstream "ImViewGizmo" widget, already vendored at `engine/ThirdParty/ImGuizmo/`) renders the axis-cube in the corner for one-click axis-snap.
- **MeshRender inspector becomes editable.** The `MeshRender` block in Node Properties gains: a Mesh row with name + "Browse…" button (opens an asset picker modal listing `Scene::Manager()->ForEach<Mesh>()`) + "Jump to asset in Content Browser" button (selects and scrolls the tile into view). Same for each Material slot. Changing the mesh or a material slot calls `MeshRender::SetMesh` / `SetMaterial` and refreshes the node's model AABB.
- **Jump-to-asset from inspector.** A small "→" button next to each bound mesh/material name in the inspector selects the asset in the Content Browser and focuses it. This is the inverse of double-click-to-edit.
- **Thumbnails.** Texture thumbnails reuse the existing `ImGui::Image((ImTextureID)(intptr_t)tex->GetID(), ImVec2(48,48), ImVec2(0,1), ImVec2(1,0))` pattern from `EditorNodeProperties.cpp:304`. Mesh thumbnails are rendered off-screen to a small FBO per visible tile (one FBO per mesh, cached on the mesh's `BufferId`), drawn with the mesh's first material or a fallback flat shader, camera framed by the mesh's AABB.

## Capabilities

### New Capabilities
- `asset-editor-windows`: Modal per-asset viewer/editor windows (one for Mesh, one for Material) that walk serializable properties and render typed editors; the Mesh editor includes a centered 3D preview with rotate/zoom + `ImGuizmo::ViewManipulate` axis-cube.
- `asset-unique-naming`: Engine-level `UniqueName(base, existsPredicate)` helper lifted from the editor-only `UniqueChildName`, used by both asset rename/duplicate and node rename/duplicate so the suffix scheme (`Name`, `Name (1)`, `(copy)`, `(copy 2)`) is identical.
- `confirm-dialog`: Reusable `Editor::ConfirmDialog` modal (title + message + Yes/No callback) following the existing flag-then-`OpenPopup` pattern.

### Modified Capabilities
- `editor-shell`: The Content Browser requirement changes from "list directory files" to "render in-scene mesh/material assets as an icon grid with thumbnails, context menu (Duplicate/Rename/Delete), double-click-to-edit, and external selection API (select + focus from other windows)". The `selected_file` string is replaced with `selected_asset` (type + name).
- `scene-inspector-component-panel`: The MeshRender section requirement changes from read-only display to editable rebinding — mesh row + per-slot material rows each get a "Browse…" picker (modal listing `EntityManager::ForEach<T>`) and a "Jump to asset in Content Browser" button. Cast Shadows checkbox stays.

## Impact

- **Code touched:**
  - `engine/Fury/Editor/EditorWindows.cpp` — `RenderContentBrowserWindow` rewritten (grid layout, thumbnails, context menu, double-click, external selection); `UniqueChildName` / `DoDuplicate` lifted out of anonymous namespace.
  - `engine/Fury/Editor/EditorNodeProperties.cpp` — `RenderMeshRenderBody` extended with mesh/material picker + jump-to-asset; `RenderMaterialSectionBody` reused by the new asset editor window.
  - `engine/Fury/Editor/Editor.cpp` / `Editor.h` — new `ConfirmDialog` API; new `SelectAssetInBrowser(type, name)` API; modal registration for asset editor windows.
  - New files: `engine/Fury/Editor/EditorAssetWindows.cpp` (mesh/material editor windows), `engine/Fury/Editor/EditorConfirmDialog.cpp`/`.h`, `engine/Fury/EntityUtil.h` (or `Entity.h` method) for `UniqueName`.
  - `engine/Fury/EntityManager.h` — possibly a `NameExists<T>(name)` helper to back the predicate.
  - `engine/CMakeLists.txt` — add the new editor source files to `FURY_EDITOR_SRC`.
- **Dependencies:** `ImGuizmo::ViewManipulate` is already vendored at `engine/ThirdParty/ImGuizmo/` and does not need to be added. The mesh thumbnail FBO/render reuses existing `Pipeline` / `Texture::GetTemporary` / `FrameBuffer` infrastructure (same pattern as `EditorWindows.cpp` Profiler Shadows tab blit path).
- **Scene format:** No change to `scene.json` / `scene.bin` shape. Asset names are already the identity; this change just enforces uniqueness at edit time and exposes the existing data in the UI.
- **Non-goals:** External asset files (loading `.mesh`/`.mat` from disk as separate files), UUID/GUID system, asset import pipelines into the Content Browser, drag-drop from Content Browser into the viewport, and material/shader graph editing are all out of scope.
