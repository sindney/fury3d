# body-setup-component

## Purpose

The `BodySetup` component: per-node collision authoring data (shape type,
motion type, shape parameters, physical material fields), its scene
serialization, inspector registration, and the runtime construction of Jolt
shapes/bodies from it.

## Requirements

### Requirement: BodySetup SHALL be a serializable component registered under the name "BodySetup"

`BodySetup` SHALL subclass `fury::Component`, implement `Clone`/`Load`/`Save`,
and be registered in `SceneNode::ComponentRegistry` as `"BodySetup"`. Its
serialized fields SHALL include: `shapeType` (`mesh` | `box` | `sphere`,
default `mesh`), `motionType` (`static` | `dynamic`, default `static`),
`collisionMesh` (mesh asset name; empty means use the sibling `MeshRender`'s
mesh), `halfExtents` (Vector4), `radius` (float), `mass`, `friction`,
`restitution`. Scenes saved with BodySetup SHALL round-trip through
`FileUtil::SaveCompressedFile` + load with all fields intact.

#### Scenario: Round-trip preserves body setup

- **WHEN** a node has a BodySetup with `shapeType=box`, `motionType=dynamic`, `mass=25`, `friction=0.8`
- **AND** the scene is saved and reloaded
- **THEN** the reloaded BodySetup has identical field values

#### Scenario: Scene without BodySetup loads unchanged

- **WHEN** a pre-physics scene (no BodySetup components) is loaded
- **THEN** load succeeds with no warnings about missing component types

### Requirement: BodySetup SHALL appear in the inspector and Add Component flow

The Node Properties panel SHALL list BodySetup as a collapsible, removable
section (all fields editable), and the Add Component popup SHALL offer it when
the selected node lacks one. The section SHALL include an "Open Body Setup
Editor…" button that opens the BodySetup editor window for that node.

#### Scenario: Add BodySetup via inspector

- **WHEN** the user selects a node with a MeshRender and chooses "BodySetup" from Add Component
- **THEN** a BodySetup section appears with `shapeType=mesh` defaulting to the render mesh
- **AND** the scene is marked dirty

### Requirement: Mesh shape SHALL default to the node's render mesh and support explicit collision mesh references

With `shapeType=mesh` and empty `collisionMesh`, the collision shape SHALL be
built from the sibling `MeshRender` component's base mesh (not an active LOD).
Setting `collisionMesh` to a mesh asset name SHALL use that mesh instead.
Multi-submesh meshes SHALL contribute all submesh index arrays with correct
vertex offsets. Shape construction SHALL occur while the mesh's CPU-side
vertex/index data is present; a mesh referenced by any BodySetup SHALL retain
its CPU data (the `DeleteRawData` path SHALL skip it).

#### Scenario: Default mesh collider matches render geometry

- **WHEN** a node with a MeshRender gets a default BodySetup and the scene plays
- **THEN** the character controller stands on the render mesh's visible surface

#### Scenario: Simplified collision mesh asset is used when referenced

- **WHEN** `collisionMesh` names a simplified mesh asset generated by the BodySetup editor
- **THEN** the Jolt shape is built from the simplified mesh's triangles, not the render mesh

### Requirement: Static mesh shapes SHALL bake the world transform into the shape

For `motionType=static`, the collision geometry SHALL be transformed by the
node's world matrix at build time and the Jolt body placed at identity, so
scaled ancestors (e.g. the ×100 `RootNode`) require no runtime scale handling.
Static bodies SHALL be non-moving in the broadphase.

#### Scenario: Rock under ×100 root collides at its rendered position

- **WHEN** a rock node nested under the ×100 `RootNode` has a static mesh BodySetup
- **AND** the capsule character walks to the rock's rendered location
- **THEN** the capsule is blocked exactly at the rock's visible surface

### Requirement: Dynamic bodies SHALL bake scale into shape dimensions and drive their node

For `motionType=dynamic`, box/sphere shapes SHALL bake the node's world scale
into extents/radius; a `mesh` shape on a dynamic body SHALL fall back to a
convex hull of the referenced mesh and log the fallback once. Dynamic bodies
SHALL write their simulated world transform back to the owning node every
frame (per the physics-world sync requirement). `mass`, `friction`, and
`restitution` SHALL map to the Jolt body creation settings.

#### Scenario: Dynamic crate falls, tumbles, and rests

- **WHEN** a cube node with `motionType=dynamic`, `shapeType=box` starts above the ground
- **AND** the scene plays
- **THEN** the cube node visibly falls, collides with the ground collider, and comes to rest on it

#### Scenario: Dynamic mesh body falls back to convex hull

- **WHEN** a dynamic BodySetup uses `shapeType=mesh` on a rock mesh
- **THEN** the body is created from a convex hull of the rock mesh
- **AND** a single log line records the mesh→hull fallback

### Requirement: Box and sphere shapes SHALL auto-fit from the mesh AABB and stay editable

On adding BodySetup (or switching shape type), `halfExtents`/`radius` SHALL
initialize from the sibling mesh's local-space AABB. Edited values SHALL be
respected exactly at body-creation time (scaled by the node's world scale).

#### Scenario: Auto-fit box matches mesh bounds

- **WHEN** a user adds BodySetup to a node whose mesh AABB spans 200×100×50 local units and picks `box`
- **THEN** `halfExtents` initializes to (100, 50, 25)
- **AND** the resulting Jolt box matches those extents under world scale
